# Nginx 프록시 회귀 검증

Node.js 24와 Docker 접근 권한이 있는 환경에서 저장소 루트에서 실행한다. 별도 패키지 설치는 필요하지 않다.

```bash
node --test tests/nginx/*.test.mjs
```

고유한 Docker 네트워크와 테스트용 컨테이너를 만들고, 실제 `front/nginx.conf`를 Nginx에 마운트한다. 백엔드 대신 요청 경로·헤더·TCP 포트를 반환하는 작은 HTTP 서버를 사용하며, 호스트에는 임의의 `127.0.0.1` 포트만 공개한다. 기존 Compose 서비스·Redis·대회 데이터·운영 비밀번호는 사용하지 않는다. 정상 종료와 테스트 실패 시 생성한 컨테이너와 네트워크를 정리한다.

다음을 실제 HTTP 요청으로 확인한다.

- `nginx -t` 통과, `/api/search`가 `/search`로 전달되고 반복 `handle` 쿼리를 유지한다.
- `Host`, `X-Forwarded-For` 전달과 백엔드 HTTP/1.1 연결을 유지한다.
- 순차 요청 20건이 백엔드 TCP 연결을 재사용한다. 최대 2개 포트만 허용하며 이번 실행에서는 1개를 사용했다.
- 기존 백엔드 IP를 별도 컨테이너에 할당해 재사용을 막고, 다른 IP의 백엔드로 교체한다. 프론트엔드를 재시작하지 않고 최대 45초 동안 새 백엔드로의 연결을 확인한다.

현재 Docker 이미지 태그는 `nginx:stable-alpine`과 `node:24-alpine`이다. 실행 환경에 이미지가 없으면 Docker가 내려받으며, 사용한 Nginx 버전을 테스트 출력에 기록한다. `resolve` 설정을 사용하므로 Nginx 1.27.3 이상이 필요하다. 이미지 태그가 가리키는 버전이 바뀌면 측정값도 달라질 수 있다.

[변경 전후 부하 비교 결과](REPORT.md)는 실제 Spring 백엔드·Redis와 모의 Codeforces API를 사용한 별도 실행 결과다. 그 부하 도구는 `perf/search-load-tests` 작업에서 보관한 것을 임시 작업 공간에 복원해 사용했으며, 위 회귀 테스트는 해당 도구 없이 실행할 수 있다.
